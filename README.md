# ЛР № 1. Экранный доступ в Windows

Учебный проект: невизуальная навигация, UI Automation, барьеры доступности и исправление доступного имени кнопки.

Учебная группа: **указать**. Имена опубликованы по запросу команды.

> **Статус: подготовительные материалы, не завершённый эксперимент.** HTML-форма, код исправления, схема, снимки браузера и ролик подготовлены. Навигация участников с NVDA, инспекция Windows UIA, события и тесты в Windows ещё не выполнены. Скриншоты и видео сняты в Chromium на Linux и не являются подтверждением Windows-проверок.

## Запуск

1. Скачайте репозиторий через Code → Download ZIP, распакуйте.
2. При наличии Python в папке проекта выполните `python -m http.server 8000`.
3. Откройте `http://localhost:8000` в Microsoft Edge.
4. Можно открыть `before/index.html` напрямую; для повторяемого эксперимента рекомендуется локальный сервер.
5. Следуйте [пошаговому сценарию](docs/WINDOWS-CHECKLIST.md).

## Что исправлено

Кнопка содержит SVG с `aria-hidden="true"` и не содержит текста. В версии «до» нет источника доступного имени. В версии «после» добавлено `aria-label="Поиск"`. Внешний вид одинаков; поясняющий баннер версии отличается. Поле поиска намеренно остаётся без label/aria-label.

## Проверки проекта

`node scripts/test-browser.cjs` запускает локальные проверки через Playwright (нужен установленный пакет `playwright` и Chromium). Проверяются имя кнопки в браузерном DOM, ввод, флажок, модальный диалог, отдельное окно и адаптивность. Это **не** тест NVDA и не инспекция UI Automation.

Бинарные медиа восстанавливаются из `media-source/` командой `python scripts/restore-media.py`; при публикации это также делает workflow. SHA-256 проверяется перед записью. Формат исходников медиа — сжатый base64, а не данные эксперимента.
