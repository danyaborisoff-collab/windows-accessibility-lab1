# Ожидаемые результаты для дополнения отчёта

**Статус: предположения и примеры, не измерения.** Таблицы дополняют места, для которых нет записи инспектора, речи или клавиш. Их нельзя трактовать как журнал работы команды. Состояния ниже предполагают видимые и включённые элементы, без ошибок загрузки и блокирующих окон.

## 1. Объекты веб-страниц

| Объект | Предполагаемая роль | Пример доступного имени | Ожидаемое состояние / значение | Пример речи, не запись |
|---|---|---|---|---|
| Поиск Bing | Edit или ComboBox с подсказками | «Поиск»; точное имя зависит от разметки | Доступен; текст «france football»; подсказки раскрыты | «Поиск, поле ввода, france football» |
| Поиск Transfermarkt | Edit | «Поиск»; имя может отличаться или отсутствовать | Доступен; значение «Lamin Yamal» | «Поиск, редактор, Lamin Yamal» |
| Результат Lamine Yamal | Hyperlink | Lamine Yamal | Доступен; возможен фокус | «Lamine Yamal, ссылка» |
| Кнопка аудиоплеера | Button | «Воспроизвести» или Play | Доступна; при запуске имя может смениться на «Пауза» | «Воспроизвести, кнопка» |
| Кнопка согласия cookies | Button | oui j’accepte | Доступна, если баннер открыт | «oui j’accepte, кнопка» |

Внешний вид не позволяет установить точное имя, роль и значение IsKeyboardFocusable. Роль поиска Bing может быть представлена иначе разными слоями браузера. Пустой Name нельзя исключить только по видимой подписи.

## 2. Возможный сценарий навигации

| Этап | Предлагаемые команды | Ожидаемый итог |
|---|---|---|
| Поиск в Bing | Перейти к полю Tab или командой NVDA для полей; при необходимости NVDA+Space; ввести запрос | В поле появляется «france football» |
| Раздел Transfermarkt | Найти ссылку Tab или через NVDA+F7; Enter | Открывается раздел трансферов |
| Поиск игрока | Перейти в поле; ввести «Lamin Yamal»; отправить форму | В выдаче виден Lamine Yamal |
| Профиль и аудио | Активировать ссылку; перейти на кнопку плеера; Enter или Space | Открывается профиль; запускается воспроизведение, если браузер разрешает |
| Просмотр брайля | Меню NVDA → Инструменты → Просмотр брайля | Появляются брайлевские точки и текстовая строка текущего объекта |

Это предложенный путь, не восстановленные нажатия. Число Tab и длительность тренировки не выдумывались. Голос, синтезатор и настройку клавиши NVDA нельзя определить по снимкам; Insert используется здесь как условный пример.

## 3. Речь и брайль для одного объекта

На снимке фактически видна строка `https://www.lequipe.fr/France-Football`. Если текущий объект — ссылка с таким доступным именем, возможна речь «https://www.lequipe.fr/France-Football, ссылка». Если фокус относится к другому типу объекта, роль и фраза будут другими. В речи адрес может произноситься пословно или посимвольно согласно настройкам; брайль отображает строку пространственно. Это объяснение возможного различия, не доказательство того, что NVDA произнёс именно такую фразу.

## 4. Пять элементов локальной формы: ожидаемая модель UIA

| Элемент | ControlType | Name | Значение | Основные Patterns |
|---|---|---|---|---|
| searchBtn, before → after | Button | пусто → Поиск | Не применяется | Invoke |
| searchInput | Edit | Пусто | Пустая строка; затем введённый запрос | Value, возможно Text |
| name | Edit | Имя | Пусто → Анна | Value, возможно Text |
| volume | Slider | Громкость | RangeValue.Value: 50 → 70 | RangeValue |
| agree | CheckBox | Согласен с условиями | ToggleState: Off → On | Toggle |

Для видимого включённого состояния ожидаются IsEnabled=true, IsOffscreen=false; для стандартных интерактивных контролов — IsKeyboardFocusable=true. HasKeyboardFocus=true ожидается только у текущего элемента, остальные не должны одновременно получать фокус. Родитель предполагается именованной областью/группой «Заявка на консультацию», но конкретный узел и промежуточные контейнеры зависят от дерева Edge. Value не применяется к кнопке; состояние флажка берётся из TogglePattern, а число ползунка — из RangeValuePattern.

## 5. Предполагаемые события и речь

| Действие | Что ожидается в UIA | Возможная речь NVDA |
|---|---|---|
| Фокус на кнопке before | FocusChanged, Button с пустым Name | «Кнопка» |
| Фокус на кнопке after | FocusChanged, Button «Поиск» | «Поиск, кнопка» |
| Ввод «Анна» | PropertyChanged для Value.Value, если провайдер публикует уведомление | Посимвольное эхо, если включено |
| Ползунок 50 → 70 | PropertyChanged для RangeValue.Value | «70» или значение с единицей |
| Включение agree | PropertyChanged для ToggleState | «Отмечено» |
| Открытие HTML-диалога | Смена фокуса внутри диалога; WindowOpened не гарантирован | Название диалога и элемент фокуса |
| Новое окно справки | WindowOpened, затем события фокуса, если создано новое окно | «Справка — ЛР 1» |

Посимвольное эхо не доказывает получение UIA-события Value. Наличие событий и их аргументы следует проверить в конкретной версии Edge. Дата, время и RuntimeId не моделировались.

## 6. Ожидаемые результаты тестов

- **Позитивный:** после добавления aria-label ожидаются Name=«Поиск», роль Button и понятная реплика; активация выполняет тот же локальный поиск.
- **Негативный:** у searchInput нет подписи, поэтому ожидается пустой Name; NVDA может сообщить только роль/значение. Точная фраза зависит от контекста.
- **До/после:** имя кнопки меняется с пустого на «Поиск»; роль, действие и внешний вид сохраняются. Позитивный сценарий можно считать пройденным в Windows только после фактической проверки.

Фактически уже выполненные браузерные тесты Linux описаны отдельно в BROWSER-CHECKS.json. Этот раздел не меняет их происхождение и не объявляет Windows-проверки выполненными.
