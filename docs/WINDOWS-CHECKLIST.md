# Практический сценарий в Windows

## Подготовка
1. Установить NVDA с https://www.nvaccess.org/download/ и Accessibility Insights for Windows с https://accessibilityinsights.io/downloads/.
2. Зафиксировать Windows (`Win+R` → `winver`), версии NVDA и Edge.
3. Выучить NVDA+Q (выход), Ctrl (остановить речь). Клавиша NVDA обычно Insert или настроенный Caps Lock.
4. В NVDA → Инструменты включить «Просмотрщик речи» для точного переноса фраз и «Просмотр брайля». Использовать тестовые, а не личные данные.

## Часть 1 — привычный ресурс
1. Выбрать регулярно используемый сайт/приложение; записать название и URL/версию.
2. Освоить навигацию 10–15 минут: Tab, Shift+Tab, Enter, Space. В веб-контексте режим обзора и режим фокуса различаются; при необходимости NVDA+Space.
3. Отвернуть экран. Каждый участник выполняет минимум одно действие лично; всего пять действий. Не подсказывать исполнителю визуальное положение элементов.
4. Записать имя исполнителя, цель, клавиши, дословную речь, результат и затруднения. Неудача тоже наблюдение.
5. Вернуть экран, сопоставить минимум три объекта с речью: вид, имя, роль, состояние.
6. На одном объекте сравнить речь и фактическую строку просмотрщика брайля; сделать снимок.
7. Рассмотреть архитектурную схему и адаптировать подписи к своей связке.

## Часть 2 — тестовая форма
1. Открыть before/index.html в Edge, желательно через локальный сервер из README.
2. Запустить Accessibility Insights → Live Inspect. Выбирать элементы мышью или фокусом согласно возможностям установленной версии.
3. Для searchBtn, searchInput, name, volume, agree записать ControlType, Name, Value, IsEnabled, IsOffscreen, IsKeyboardFocusable, ToggleState (если применим), Patterns и родителя. Снять Details.
4. Начать запись в Events. Настроить наблюдение так, чтобы попадали фокус, изменения нужных свойств и новые окна. Названия и расположение настроек могут различаться.
5. Перевести фокус; ввести «Анна» в «Имя»; изменить ползунок; открыть HTML-диалог; закрыть; открыть отдельное окно справки. Записать фактически пришедшие события. Для значения допустим ползунок и RangeValue.Value, если ввод в поле не даёт ожидаемого события.
6. Если нет WindowOpened: проверить настройки записи, разрешение popup, создание именно нового окна (закрыть прежнее окно lab1-help). Не объявлять событие полученным без записи.
7. По реальной работе NVDA и инспектора описать два барьера.
8. Сравнить before и after: в after добавлено aria-label="Поиск".
9. Позитивный тест: у исправленной кнопки имя «Поиск», NVDA сообщает назначение, Enter вызывает локальный статус.
10. Негативный тест: поле поиска всё ещё без имени — подтвердить сохранение барьера.
11. Заполнить сравнение до/после реальными свойствами и речью.

## Доказательства для отчёта
- Версии Windows/NVDA/Edge.
- Протокол пяти действий с четырьмя реальными исполнителями.
- Снимок просмотрщика брайля и запись соответствующей речи.
- Снимки Live Inspect и Events.
- Имя кнопки до и после, плюс фразы NVDA.
- Результаты тестов и вывод 5–10 предложений.
