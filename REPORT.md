### 8. Архитектура

![Архитектура экранного доступа](assets/architecture.svg)

Пользователь работает клавиатурой. Часть команд обрабатывает скринридер, остальные передаются приложению обычным путём ввода. UIA-клиент может запрашивать свойства дерева и вызывать действия через поддерживаемые паттерны. Приложение/его провайдер публикует свойства элементов и события. Скринридер преобразует полученные данные в речь и брайлевское представление.

UI Automation — фокус этой лабораторной, но не единственный интерфейс доступности: конкретная связка NVDA, браузера и приложения может использовать также IAccessible2, MSAA и другие механизмы. Схема не утверждает, что любой NVDA всегда работает исключительно через UIA.

### 4. Два заложенных барьера

1. **Кнопка поиска** → декоративный SVG скрыт от accessibility tree, текста и aria-label нет → назначение кнопки невизуально неясно → открыть before, перейти Tab на первую кнопку; проверить Name и записать речь. Статус: заложено в коде, влияние на NVDA/Windows не проверено.
2. **Поле поиска** → нет связанного label или aria-label → пользователь не получает название поля при фокусе → перейти Tab на поле после кнопки; проверить Name и записать речь. Статус: заложено в коде, влияние на NVDA/Windows не проверено.

### 5. Исправление кнопки

До:

```html
<button id="searchBtn">
  <svg aria-hidden="true" width="20" height="20" viewBox="0 0 24 24">…</svg>
</button>
```

После:

```html
<button id="searchBtn" aria-label="Поиск">
  <svg aria-hidden="true" width="20" height="20" viewBox="0 0 24 24">…</svg>
</button>
```

Внутреннее содержимое SVG одинаково, многоточие сокращает его в отчёте. Полные файлы — в before/after. Изменён только атрибут имени кнопки; поясняющий баннер страницы также меняется для различения версий. Сам внешний вид кнопки не меняется.
